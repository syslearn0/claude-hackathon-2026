# トイレ外出サポート

**Built with Claude: Japan 2026 応募作品**
公開版：https://claude-hackathon-2026-sigma.vercel.app/

急なトイレの不安がある人（クローン病・潰瘍性大腸炎・過敏性腸症候群など）の外出を、**確かめた事実の情報**で支える Web アプリ。
作者自身がクローン病の当事者。

> **English summary** — A web app for people with urgent bowel needs (IBD, IBS, etc.) going out in Japan. It tells you what map apps don't: whether a toilet is inside or outside the ticket gates, which floor, how many minutes from the platform (measured on site), whether you can change clothes there, and which nearby shop sells spare underwear — and where on the shelf. Claude plans per station and re-checks emergencies in parallel, but can only cite places its tools actually returned: the structured-output schema is rebuilt every turn so place IDs are an enum of tool results.

---

## 1. なぜ作るか

- 地図アプリは「トイレがある」ことは教えてくれる。でも**改札の内か外か、何階か、混んでいたら次はどこか**は教えてくれない。巨大な駅（新宿など）では、それが分からないと間に合わない。
- 当事者への聞き取り（匿名化して要点のみ記録）で分かったこと：
  - **急なときは、スマホで調べる余裕がない**
  - 困るのはトイレの場所だけではない。**汚してしまった後**（捨てる場所・替え・着替える場所）、**急に動けなくなる**こと
  - 一番困っているのは**診断から間もない人**。経験の長い人の「この辺にありそう」という勘がまだない
- この作品は、その勘と工夫を、誰でも使えるデータと手順にする。

## 2. できること

| 場面 | 画面 | 中身 |
|---|---|---|
| **出かける前**（今日は調子が悪い日） | `/plan` | 乗換アプリの経路を貼るか「共有」すると、経路の駅ごとに、使えるトイレ・着替えられる場所・替えを買える店・持ち物をまとめた計画を作る（AI）。声でも入力できる |
| **急に来たとき** | `/now` | 押すだけ。一番近いトイレを大きく出す（AI を待たない）。駅の中では方角ではなく「改札内・2F・ホームの階段から約2分」。地図・お願いカード・Google マップへの受け渡し |
| **移動中・並行の見直し** | `/now` | GPS の動きから「乗り物の中」かを推定し、電車の中なら**次の駅**のトイレを出す。オンにすると、AI が並行して状況を判断し直し、違うときだけ理由つきで別の候補を出す |
| **トイレに入った後** | `/now` | 「下着を汚した」「着替えたい」などを選ぶと、替えを買える店（確認済みなら品目と売り場）→ 着替えられる場所 → 帰るか続けるか、の手順を出す（AI。使えないときは AI なしの簡易版） |
| **自分の情報** | `/me` | 使うトイレの側、多機能トイレが要るか、替えを持ち歩くか、よく使う駅、お願いカードの文面、緊急連絡先。スマホの中だけに保存。病名の欄はない |
| **お願いカード** | `/now` | 「急いでトイレを使わせてください」を画面いっぱいに出す（英語も）。話す余裕がないときに、駅員や店員に見せる |

ホーム画面に追加すると、Android では乗換アプリの「共有」から経路を直接送れる。

## 3. Claude の使い方

**AI に考えさせるところと、プログラムで決めるところを分けている。**

| AI（Claude） | プログラム |
|---|---|
| 状況や経路の文を読む、どの場所をどの順で使うか決める、理由を書く | 距離・方角・歩く時間、近い順の並べ替え、乗り物の中かの推定、駅の中かの判定、回数制限 |

- **道具（tools）**：駅を探す、近くのトイレ・店を探す、場所の詳細、都営の運行情報。事実はすべて道具から。
- **作り話の場所を「書けない」仕組み**：返答は決まった JSON（構造化出力）。手順ごとの `place_ids` は、**その回に道具が返した id だけを並べた enum** にして、送るたびにスキーマを作り直す。道具がまだ何も返していなければ、場所はそもそも書けない。念のため、プログラムでも確かめる。
- **名前・方角・分数・営業時間・品ぞろえは AI に書かせない**。画面がデータから出す。AI が書くのは「やること」と「理由」だけ。
- **緊急時は AI を待たない**。プログラムが0秒で候補を出し、AI は並行して見直す（約15秒）。違うときも一番の候補を黙って差し替えない。
- **線引き**：症状の判断・受診・食事・薬の助言はしない。危険な状態が書かれたときは決まった一文で医療機関・119番を案内するだけ。病名を繰り返さない。
- モデル：Claude Sonnet 5.5 と Opus 5.5 を評価で比べた（[評価](#5-評価)）。`ANTHROPIC_MODEL` で切り替える。拒否されたときは server-side fallback。
- 開発は Claude Code で行った（設計の相談、実装、テスト、データの取り込み、本物の API での確認）。

### Claude Code での作り方

道具は「使ったかどうか」ではなく、**この作品で守りたいもの**に合わせて選んだ。設定はすべて `.claude/` にあり、誰が clone しても同じように動く。

| 守りたいもの | 道具 | 中身 |
|---|---|---|
| 個人の情報を公開しない | **フック**（PreToolUse）`.claude/hooks/guard-commit.mjs` | Claude がコミットしようとすると、その前に中身を調べる。現地調査の生の記録・GPS の記録（家の位置が分かる）・鍵・携帯電話の番号が入っていればコミットを止め、理由を返す。「気をつける」ではなく「できない」にした |
| 現地確認を毎回同じ質で取り込む | **スキル** `/import-survey` | 協力者の記録を、1件ずつ確かめてから取り込む（必須項目、推測で埋めていないか、打ち間違いらしい秒数、メモに人の名前や番号がないか、公式との食い違い）。取り込んだあと、画面に「現地確認」で出るところまで確かめる。協力者が増えても同じ手順で回せる |
| データの値が出典と合っている | **サブエージェント** `source-checker`（Haiku） | 号車の表を1項目ずつ鉄道会社の公式ページと突き合わせる。量が多く単純なので安いモデル |
| 当事者を傷つけない言葉 | **サブエージェント** `wording-reviewer`（Sonnet） | 画面・AI への指示・AI の返答を当事者の目で読み、気休め・医療の助言・責める言い方・急いでいる人に長すぎる文を探す。作った本人とは別の目で読ませる |
| 画面が本当に動く | **MCP**（Claude のブラウザ操作） | 開発サーバーの画面を Claude が開いて押し、地図・駅モード・共有の受け取りなどを確かめた |

**モデルの使い分け**：設計と最終確認は Opus、量の多い作業は Sonnet や Haiku のサブエージェントに任せ、結果は Opus が確かめてから取り込む。

実際に見つかって直したもの（2026-11-03）：
- **source-checker**：号車の表8路線のうち、新幹線の弱冷房車の記述に出典がなく、丸ノ内線は出典のページを開けなかった。→ 新幹線の弱冷房車は「未確認」に戻し、丸ノ内線は「公式資料で未確認」と出すようにした。読み違い（発表日と開始日の取り違え）もあったので、結果はそのまま信じず確かめてから直した。
- **wording-reviewer**：緊急の画面に「上の候補へ向かって大丈夫です」が残っていた（AI には禁じていた言葉）。AI の返答では、薬を聞かれて「薬剤師か医師に聞いて」と勧める、データで確かめていない店を「買えます」「確実」と言い切る、「道具」という内部の言葉が出る、などが見つかった。→ 画面と簡易版の文を直し、AI への指示に「言い切らない」「summary は短く」「notes は3つまで」を足し、評価の禁止語にも加えた。
- **階をそろえる作業**（Sonnet）：新宿駅の屋内データの階を日本式にそろえさせたところ、店1軒の書き方を周り50件に広げて、新南改札だけを南口と別の階にしていた。Opus が改札の階を確かめて見つけ、「2つ以上の手がかりが一致したときだけ」に直した。

## 4. データ

| 段 | 中身 | 出典・ライセンス |
|---|---|---|
| 現地確認済み | 改札の内外、階、ホーム・改札から測った秒数、男性個室のサニタリーボックス、石鹸、ベンチ、駅員窓口、店の品ぞろえと売り場 | 協力者の現地確認（`/tools/survey` で記録、`npm run import:survey`） |

| OSM | 新宿・東京・京都の各駅周辺と京阪沿線のトイレ・コンビニ・ドラッグストア、東京23区と京都市の駅の位置、新宿駅の屋内データ | © OpenStreetMap contributors（ODbL 1.0） |
| 車内設備 | 車内トイレのある号車・弱冷房車 | 各鉄道会社の公式の案内（項目ごとに出典と確認日） |

調べて分かったこと：公式データでも**改札の内外が分かるのは 782 件中 13 件だけ**。地図アプリにない情報は、現地で確かめるしかない。

## 5. 評価

`npm run eval`（[scripts/eval.ts](scripts/eval.ts)、質問は [eval/questions.json](eval/questions.json)）。結果は [eval/results/](eval/results/)。

20 問：トイレに入った後 6・出かける前の計画 6・緊急時の見直し 5・わざと誤らせる質問 3（データにない噂のトイレへの案内、安心させる言葉の要求、英語）。
各返答を**プログラムで自動判定**する（決まった形で返ったか、引用した場所がすべて道具の結果にあるか、「大丈夫です」・病名・薬の助言を出していないか、危険な状態で 119 の決まった文が出るか、データのない駅で場所を作らないか、電車の中なら次の駅のトイレを出すか、など）。

| モデル | 合格 | 根拠のない場所 | 応答時間（中央値） | 20 問の費用 |
|---|---|---|---|---|
| **Claude Sonnet 5.5**（言葉づかいを直したあと） | **20 / 20** | **0** | **6.4 秒**（トイレの後 6.3・計画 8.4・緊急 6.3） | $0.55 |
| Claude Sonnet 5.5（直す前） | 20 / 20 | 0 | 13.1 秒（11.3・14.2・11.9） | $0.59 |
| Claude Opus 5.5（直す前） | 20 / 20 | 0 | 18.1 秒（17.1・24.6・13.7） | $1.45 |

- 応答時間は時間帯で揺れる（同じ質問集で Sonnet は中央値 8〜13 秒、Opus は 16〜18 秒）。表は最後の実行（[eval/results/](eval/results/)）。
- 根拠のない場所が 0 なのは偶然ではなく仕組み（`place_ids` を道具の結果の enum に縛る）による。
- **評価で見つかって直したこと**：
  - 「まだ動けない」で「個室にいて大丈夫です」と言うことがあった（3 回に 1 回）。禁止を足すだけでは減らず、「頼れる手段を事実として書く」と**書くべきことを指示**して 0 になった。
  - Opus が手順の文に場所の印をそのまま書き、`place_ids` を空にしたことがあった。画面に印の文字が出ないよう、プログラムで印を文から外し、道具が返した場所なら `place_ids` に移すようにした。
  - wording-reviewer の指摘（[Claude Code での作り方](#claude-code-での作り方)）を受けて、禁止語に「安心・落ち着いて・医師・薬剤師・受診・道具」を足し、指示に「確かめていないことを言い切らない」「summary は短く」を足した。判定を厳しくしても 20/20 のまま、summary が短くなって応答も速くなった（薬を聞かれたときは「このアプリでは薬や食事の助言はしません。」の一文だけ）。
  - 判定が厳しすぎた 4 か所（言い換えの「低め」、断るときに噂の言葉を引用、など）は、返答を読んで判定の方を直した。
- 合格は同じで速さが倍なので、Sonnet 5.5 がよい。モデルは環境変数 `ANTHROPIC_MODEL` で切り替える（既定は Opus 5.5）。

## 6. プライバシー

- 近くを探す計算はスマホの中。現在地をこのアプリのサーバーに送らない。
- AI に送るのは、AI を使う場面で選んだ状況・書いた文・現在地だけ。保存しない。
- 自分の情報・今日の計画はスマホの中だけ。緊急連絡先は AI に送らない。
- 現地確認の生の記録・GPS の記録はリポジトリに置かない。

詳しくは公開版の「このアプリについて」（`/about`）。

## 7. 動かし方

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY を入れる（ANTHROPIC_MODEL は任意）
npm run dev
```

| コマンド | 内容 |
|---|---|
| `npm test` | テスト |
| `npm run eval` | 評価（Claude API を使う） |
| `npm run try:agent -- "質問" 駅名` | エージェントを手元で試す（`MODE=after` / `MODE=plan`） |
| `npm run fetch:osm` | OSM の取り込み |
| `npm run import:tokyo` | 東京都の駅トイレ CSV の取り込み |
| `npm run import:survey` | 現地確認の記録の取り込み |

構成：Next.js 16（App Router）・TypeScript・Leaflet・Anthropic TypeScript SDK。公開は Vercel。

## 8. これから

- **屋内マップ**：駅・ビル・商業施設の階ごとの地図に、トイレと自分の位置を重ねる。国の歩行空間ネットワークデータの形にそろえ、駅構内データが公開されたら差し替える（[調査メモ](docs/plan.md)）
- **利用者の報告**：使ったトイレに1タップで「使えた／閉まっていた」。確認日を新しく保つ
- **患者コミュニティと一緒に**：当事者の協力者が現地確認を広げる
