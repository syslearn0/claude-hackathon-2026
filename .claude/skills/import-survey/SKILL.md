# 現地確認の記録を取り込む

記録は困っている人を実際に連れて行く場所になる。**推測で埋めない・個人の情報を公開しない**の2つを最優先にする。

## 1. 置き場所を確かめる
- 記録ファイルは `data/private/survey/*.json`（gitignore 済み。**絶対にコミットしない**）。利用者から別の場所を言われたら、そこからこのフォルダへコピーする。
- 形は `{ records: [{ id, kind: "toilet"|"store", checkedAt, values }] }`。項目の意味は `src/lib/survey-fields.ts`、調査のルールは `src/app/tools/survey/rules/page.tsx`。

## 2. 取り込む前に1件ずつ確かめる（表にして利用者に見せる）
- **必須**：トイレは `station`・`gate`、店は `name`・`storeType`。欠けていれば「飛ばす候補」。
- **「分からない」「見ていない」はそのまま**（取り込み側で不明扱いになる）。値を補ったり推測で直したりしない。
- **位置**：`values.pos` が無い記録は駅の位置で代用され、画面で「おおよその位置」になる。何件あるか伝える。精度（accuracy）が 100m を超えるものも伝える。
- **秒数**：`minFromPlatform`・`minFromGate` が 0〜20分の範囲外なら打ち間違いの疑いとして伝える。
- **個人の情報**：`note`・`where`・`mismatch` に人の名前、電話番号、顔や人の様子の描写があれば、取り込む前に利用者に伝えて消すか決めてもらう（取り込みの出力には調査した人の呼び名は入らない）。
- **公式との食い違い**（`mismatch`）は一覧にして目立たせる。公式データ（`data/places/official-*.json`）の同じ駅のトイレと見比べ、どちらが正しそうかの判断は利用者に任せる。

## 3. 取り込む
```bash
npm run import:survey
```
「飛ばした」が出たら理由を伝える。駅名の書き方が違うだけ（「新宿駅」と「新宿」など）なら、取り込みスクリプト側の対応で済むか確かめる。

## 4. 画面で確かめる
- `npm test` を通す。
- 開発サーバー（`.claude/launch.json` の `web`）で `/now` を開き、「いまどこ？」で調査した駅・改札を選ぶ。取り込んだトイレが **「現地確認」** の印付きで、改札の内外・階・秒数が出ているかを見る。
- 店は「替えを買う」で、品ぞろえと売り場が出ているかを見る。

## 5. 報告とコミット
- 件数（トイレ・店）、飛ばしたもの、食い違い、利用者に決めてほしいことを短く報告する。
- コミットしてよいのは `data/places/verified-survey.json` だけ。利用者の OK を得てから。コミット前のフック（`.claude/hooks/guard-commit.mjs`）が `data/private/` や電話番号を止めるので、止められたら外して利用者に伝える。
